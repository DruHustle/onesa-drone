# Drone managed human identity

The Drone API can receive managed RS256 access and ID tokens through the registered HTTPS callback with PKCE. Configure the existing client credentials, `ONESA_IDENTITY_ISSUER=https://auth.onesa.eu/`, a dedicated `ONESA_IDENTITY_AUDIENCE`, `ONESA_IDENTITY_JWKS` containing trusted current and next public signing keys, `ONESA_IDENTITY_MAPPING_ISSUER` equal to the historically commissioned Portal issuer, and `ONESA_IDENTITY_ACCOUNT_URL` for account self-service. Refresh keys before rotation and immediately distribute emergency key removal. The native app uses the system browser and its existing independent one-use device proof. The original issuer namespace and stable user UUID keep the native encrypted account storage scope unchanged.

Run the established Drone schema initialization on the restored staging database. The default `python -m backend.app.managed_memberships /private/path/to/snapshot.json` mode is deliberately additive-only: it inserts missing grants, is idempotent, and refuses role changes. It never silently downgrades or deletes a local grant. This mode is suitable for initial migration rehearsal, not ongoing revocation.

For an authoritative refresh, the export must use this envelope: `schema_version: 1`, `product: "drone"`, the exact configured `mapping_issuer`, a non-empty `snapshot_id`, `complete: true`, integer `issued_at` and `expires_at` no more than one hour apart, and the complete `drone_memberships` array. Obtain the file SHA-256 independently through the owner-controlled export channel. Set `ONESA_IDENTITY_MAPPING_ISSUER` to the exact commissioned issuer and run `python -m backend.app.managed_memberships /private/path/to/snapshot.json --replace --expected-sha256 <out-of-band-sha256> --dry-run` first. Review the inserted/updated/deleted counts, then repeat without `--dry-run` to apply. The importer rejects a mismatched digest or issuer, incomplete, stale, expired or overlong snapshots, duplicate/invalid memberships and unknown local tenants before changing rows. Reconciliation is atomic: role downgrades and revoked memberships take effect on the next authenticated request. An empty complete snapshot additionally requires `--confirm-empty`. The expected digest is an integrity check, not a substitute for authenticating the exporter; only use a snapshot and digest obtained from the trusted Identity owner channel.

The Drone process does not currently pull or receive membership changes automatically. Until a trusted, fresh snapshot-export and refresh schedule is accepted and monitored, central workspace revocations are not immediate; keep managed identity disabled for production or operate only under an explicitly owned refresh procedure with bounded snapshot age. Product audience and role still cap tenant membership. An ordinary account without a local Drone tenant grant sees zero workspaces. Account access is separate from hardware, telemetry and recovery. Only synthetic read-access workflows have been qualified in this candidate.
